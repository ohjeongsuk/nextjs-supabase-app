# Task 008 인증 플로우 테스트 결과 — Playwright MCP

Task 008(인증 시스템 및 권한 관리) 완료 후 Playwright MCP로 검증한 인증/권한 리다이렉트 시나리오입니다.
Google OAuth 자체(계정 선택, 로그인 완주)는 외부 서비스라 자동화 범위 밖입니다 — 여기서는 **우리 코드가 세션·권한 상태에 따라 올바르게 분기하는지**만 검증합니다.

- 테스트 도구: Playwright MCP (`mcp__playwright__*`)
- 테스트 일자: 2026-08-21
- 전제: 모든 테스트는 쿠키 없는 새 브라우저 컨텍스트(비로그인 상태)에서 시작

---

## 1. 비로그인 상태 — 보호된 라우트 리다이렉트

| 경로               | 기대 동작                    | 실제 결과                    | 통과 |
| ------------------ | ---------------------------- | ---------------------------- | ---- |
| `/events`          | `/auth/login`으로 리다이렉트 | `/auth/login`으로 리다이렉트 | ✅   |
| `/admin/dashboard` | `/auth/login`으로 리다이렉트 | `/auth/login`으로 리다이렉트 | ✅   |

`/admin/dashboard`는 `proxy.ts`의 미인증 리다이렉트가 먼저 처리하므로, `(admin-dashboard)/layout.tsx`의
자체 `redirect("/admin/login")` 로직까지는 도달하지 않음 (정상 — 두 계층이 겹치지 않게 분업).

## 2. 비로그인 상태 — 인증 예외 경로

| 경로            | 기대 동작                   | 실제 결과   | 통과 |
| --------------- | --------------------------- | ----------- | ---- |
| `/join/event-1` | 리다이렉트 없이 그대로 열림 | 그대로 열림 | ✅   |
| `/admin/login`  | 리다이렉트 없이 그대로 열림 | 그대로 열림 | ✅   |

## 3. Google 로그인 트리거 및 `next` 파라미터 전달

`signInWithOAuth`가 호출하는 Google 리다이렉트 URL의 `redirect_to` 쿼리 파라미터를 디코딩해 확인.

| 시작 페이지                        | 기대 `next` 값     | 실제 확인된 값     | 통과 |
| ---------------------------------- | ------------------ | ------------------ | ---- |
| `/join/event-1` "참여하기"         | `/join/event-1`    | `/join/event-1`    | ✅   |
| `/admin/login` "Google로 시작하기" | `/admin/dashboard` | `/admin/dashboard` | ✅   |

두 경우 모두 `accounts.google.com/v3/signin/identifier`까지 정상 도달 — 이후 실제 계정 선택/로그인은
수동 테스트 또는 실계정 보유자가 별도로 확인 필요.

## 4. 관리자 권한 거부 메시지

| 경로                           | 기대 동작                          | 실제 결과                          | 통과 |
| ------------------------------ | ---------------------------------- | ---------------------------------- | ---- |
| `/admin/login?error=forbidden` | "관리자 권한이 없습니다" 문구 표시 | "관리자 권한이 없습니다" 문구 표시 | ✅   |

## 5. 로그인 상태 — role 불일치 거부 (Chrome 확장 세션, 수동 확인)

기존 실계정(`profiles.role = 'user'`)으로 로그인된 상태에서 `/admin/dashboard` 접근 시
`(admin-dashboard)/layout.tsx`가 `profiles.role`을 조회해 `admin`이 아니면
`/admin/login?error=forbidden`으로 리다이렉트하는 것을 확인함.

| 조건                                              | 기대 동작                      | 실제 결과                      | 통과 |
| ------------------------------------------------- | ------------------------------ | ------------------------------ | ---- |
| 로그인됨 + `role: user`로 `/admin/dashboard` 접근 | `/admin/login?error=forbidden` | `/admin/login?error=forbidden` | ✅   |

## 6. 미검증 항목

- **`role: admin` 성공 경로**: 실제 관리자 계정이 없어 "로그인 + role=admin → 대시보드 정상 진입"은 검증하지 못함.
  role 불일치 거부 경로가 정확히 동작하는 것으로 미루어 로직상 문제 없을 것으로 판단하나, 실제 관리자 계정
  확보 시 재검증 필요.
- **로그아웃 후 세션 정리**: `LogoutButton`의 `redirectTo` prop 분기(일반 `/`, 관리자 `/admin/login`)는
  코드 리뷰로만 확인, 실제 클릭 시나리오는 미실행.
