# Task 001 수동 테스트 체크리스트 — 라우팅 구조

Gather 앱의 Task 001(프로젝트 구조 및 라우팅 설정) 완료 후, 브라우저에서 직접 확인하는 수동 테스트입니다.
아직 실제 데이터/로직이 없는 빈 껍데기 페이지이므로, 여기서 확인하는 것은 **"라우팅 · 레이아웃 · 스타일"** 뿐입니다.

- 소요 시간: 약 20-30분
- 준비물: Chrome 또는 Edge 브라우저, Supabase 로그인 가능한 이메일 계정 (없으면 아래 3-B에서 새로 생성)
- 권장: 시크릿/프라이빗 창 사용 (기존 로그인 세션이 결과에 영향을 주지 않도록)

---

## 0. 사전 준비

- [ ] 터미널에서 `npm run dev` 실행
- [ ] 콘솔에 `Local: http://localhost:3000` 형태로 뜨는지 확인 (포트가 다르면 이후 모든 URL에서 3000 대신 실제 포트 사용)
- [ ] 브라우저에서 시크릿 창(Ctrl+Shift+N)을 새로 열기
- [ ] 시크릿 창 주소창에 `http://localhost:3000`을 입력해 서버가 응답하는지 1차 확인

---

## 1. 비로그인 상태 — 정상 예외 경로 확인

로그인하지 않은 상태에서 아래 경로들은 **리다이렉트 없이 그대로 열려야** 정상입니다.

| 경로            | 확인할 내용                                                 | 통과 |
| --------------- | ----------------------------------------------------------- | ---- |
| `/`             | 리다이렉트 없이 랜딩/홈 화면이 뜸 (주소창 URL이 `/`로 유지) | [ ]  |
| `/auth/login`   | 로그인 폼이 보임                                            | [ ]  |
| `/auth/sign-up` | 회원가입 폼이 보임                                          | [ ]  |

> 실패 시 대처: 위 3개 경로 중 하나라도 `/auth/login`으로 다시 리다이렉트되며 무한 루프가 생기면
> `lib/supabase/proxy.ts`의 예외 조건(`/`, `/login`, `/auth` prefix)이 깨진 것이므로 코드 수정이 필요합니다 (이 문서 범위 밖).

### 2-A. 알려진 버그 재현 (실패해도 정상입니다 — Task 008에서 수정 예정)

**여기서 "재현됨"이 나오는 것이 정상이며, 지금 당장 고칠 필요가 없습니다.**

| #   | 입력한 경로    | 예상되는 현재 동작(버그)                                                        | 확인              |

| 1   | `/join/abc123` | `/auth/login`으로 리다이렉트됨 (버그, 정상은 초대 미리보기가 바로 보여야 함)    | [ ] 재현됨 (정상) |

## 3. 로그인 절차

### 3-A. 기존 계정이 있는 경우

- [ ] `/auth/login`으로 이동
- [ ] 이메일/비밀번호 입력 후 "Login" 클릭
- [ ] 로그인 성공 시 `/protected`로 이동하는지 확인 (⚠️ 현재 코드가 `/protected`로 하드코딩되어 있어 `/events`로 자동 연결되지 않는 것이 **정상 동작**입니다)

### 3-B. 계정이 없는 경우 — 새로 회원가입

- [ ] `/auth/sign-up`으로 이동
- [ ] 이메일, 비밀번호, 비밀번호 확인 입력 후 "Sign up" 클릭
- [ ] `/auth/sign-up-success` 화면("Check your email to confirm")으로 이동하는지 확인
- [ ] 가입한 이메일함에서 확인 메일을 열어 링크 클릭 (Supabase 프로젝트 설정에 따라 이메일 확인이 생략될 수도 있음)
- [ ] 다시 `/auth/login`으로 이동해 방금 만든 계정으로 로그인 (3-A 절차 수행)

### 3-C. Google OAuth로 로그인 (선택)

- [ ] `/auth/login`에서 "Continue with Google" 클릭
- [ ] Google 계정 선택 및 인증 진행
- [ ] 인증 완료 후 `/protected`로 자동 이동하는지 확인

### 3-D. `/events`로 이동

로그인 후 자동으로 이동하지 않으므로, 아래 4번 섹션 테스트를 위해 지금 수동으로 이동합니다.

- [ ] 주소창에 `http://localhost:3000/events`를 직접 입력해 이동
- [ ] `/auth/login`으로 다시 튕기지 않고 "내 이벤트" 화면이 보이는지 확인 (로그인 세션이 유지되고 있다는 뜻)

## 4. 로그인 후 13개 페이지 방문 체크리스트

로그인된 상태를 유지한 채, 아래 표의 각 경로를 주소창에 **직접 입력**해 방문하며 확인합니다.

### 4-A. `(main)` 그룹 — 하단 네비게이션 있음

| 경로                    | 확인할 제목(h1) 텍스트     | 하단 네비 3개 탭 보임 | 활성 탭 하이라이트 위치                                           | 통과 |
| ----------------------- | -------------------------- | --------------------- | ----------------------------------------------------------------- | ---- |
| `/events`               | 내 이벤트                  | [ ]                   | "내 이벤트" 탭이 강조색(primary)인지                              | [ ]  |
| `/events/new`           | 새 이벤트 만들기           | [ ]                   | "새 이벤트" 탭이 강조색인지                                       | [ ]  |
| `/events/sample-1`      | 이벤트 상세 (ID: sample-1) | [ ]                   | 3개 탭 중 어느 것도 강조되지 않음 (정상, 상세 페이지는 탭에 없음) | [ ]  |
| `/events/sample-1/edit` | 이벤트 수정 (ID: sample-1) | [ ]                   | 3개 탭 중 어느 것도 강조되지 않음 (정상)                          | [ ]  |
| `/profile`              | 프로필                     | [ ]                   | "프로필" 탭이 강조색인지                                          | [ ]  |

> 참고: 하단 네비는 `pathname === href`가 정확히 일치할 때만 활성 스타일이 켜지도록 구현되어 있습니다.
> 따라서 `/events/new`, `/events/[id]` 방문 시 "내 이벤트" 탭이 같이 강조되지 않는 것이 **현재는 정상**입니다.

### 4-B. `/join/[invite_code]` — 독립 레이아웃(하단 네비 없음)

| 경로                | 확인할 제목(h1) 텍스트        | 하단 네비 안 보임 | 화면 중앙 정렬 레이아웃인지 | 통과 |
| ------------------- | ----------------------------- | ----------------- | --------------------------- | ---- |
| `/join/test-code-1` | 초대 참여 (코드: test-code-1) | [ ]               | [ ]                         | [ ]  |

> 로그인 상태에서는 이 페이지가 정상적으로 열려야 합니다 (섹션 2-A는 비로그인 상태에서만 재현되는 버그입니다).

### 4-C. `(admin-dashboard)` 그룹 — 좌측 사이드바 있음

| 경로               | 확인할 제목(h1) 텍스트 | 좌측 사이드바(메뉴 4개) 보임 | 활성 메뉴 하이라이트 위치                | 통과 |
| ------------------ | ---------------------- | ---------------------------- | ---------------------------------------- | ---- |
| `/admin/dashboard` | 관리자 대시보드        | [ ]                          | "대시보드" 메뉴가 강조 배경(primary)인지 | [ ]  |
| `/admin/events`    | 이벤트 관리            | [ ]                          | "이벤트 관리" 메뉴가 강조 배경인지       | [ ]  |
| `/admin/users`     | 사용자 관리            | [ ]                          | "사용자 관리" 메뉴가 강조 배경인지       | [ ]  |
| `/admin/analytics` | 통계 분석              | [ ]                          | "통계 분석" 메뉴가 강조 배경인지         | [ ]  |

> 참고: 관리자 권한(role) 체크가 아직 구현되지 않아 일반 계정으로도 `/admin/*`에 들어가지는 것이 **현재는 정상**입니다

### 4-D. `/admin/login` — 독립 페이지(사이드바 없음)

| 경로           | 확인할 제목(h1) 텍스트 | 사이드바 안 보임 | 실제 로그인 입력폼은 없음(텍스트만)    | 통과 |

## 5. 반응형(모바일 vs 데스크톱) 확인

개발자도구로 뷰포트를 전환하는 방법:

1. `F12` 또는 `Ctrl+Shift+I`로 개발자도구 열기
2. `Ctrl+Shift+M`으로 기기 툴바(반응형 모드) 켜기
3. 상단 드롭다운에서 "Responsive"를 선택하고, 폭을 직접 입력해 전환

### 5-A. 모바일 뷰포트 (폭 약 375px, 예: iPhone SE)

- [ ] `/events` 접속 → 화면 하단에 3개 탭 하단 네비가 화면 폭에 꽉 차게 보이는지
- [ ] 하단 네비가 화면 최하단에 고정(fixed)되어 스크롤해도 계속 보이는지
- [ ] `/admin/dashboard` 접속 → 좌측 사이드바(폭 240px 고정)가 좁은 화면에서 콘텐츠를 과도하게 밀어내거나 겹치지 않는지 육안 확인 (현재 반응형 미대응 상태일 수 있으므로 깨져 보이면 메모만 해두고 실패로 체크하지 않아도 됨 — Task 004/006에서 다듬을 예정)

### 5-B. 데스크톱 뷰포트 (폭 약 1280px 이상)

- [ ] `/events` 접속 → 하단 네비가 화면 폭 전체에 걸쳐 보이는지 (모바일 전용 UI라 데스크톱에서도 동일하게 나오는 것이 현재는 정상)
- [ ] `/admin/dashboard` 접속 → 좌측 사이드바 + 우측 콘텐츠 영역이 나란히 2단 레이아웃으로 보이는지

## 6. 다크모드 확인

> **주의**: 새로 만든 13개 페이지에는 화면 안에 라이트/다크 전환 버튼이 없습니다
> (`ThemeSwitcher` 컴포넌트는 현재 `/protected` 페이지에만 있고 신규 페이지들에는 아직 추가되지 않았습니다).
> 따라서 아래처럼 개발자도구로 시스템 테마를 에뮬레이션해서 확인합니다.

1. 개발자도구 열기 (`F12`)
2. `Ctrl+Shift+P`로 명령 팔레트 열기 → `Rendering`을 입력해 "Show Rendering" 선택
3. 하단에 뜨는 Rendering 탭에서 "Emulate CSS media feature prefers-color-scheme"을 `dark`로 변경

### 확인 항목 (다크 모드 상태에서)

- [ ] `/events` — 배경/글자색이 반전되고, 하드코딩된 흰 배경이나 검정 글자로 인해 안 보이는 텍스트가 없는지
- [ ] `/admin/dashboard` — 사이드바 배경(`bg-card`)과 본문 배경(`bg-background`)이 서로 구분되면서도 자연스러운지
- [ ] `/join/test-code-1` — 중앙 정렬 카드/텍스트가 다크 배경에서도 잘 보이는지
- [ ] 전체적으로 색이 깨지거나(예: 흰 배경에 흰 글씨) 대비가 부족한 부분이 없는지

4. 확인이 끝나면 Rendering 탭에서 다시 `light`로 변경해 라이트 모드도 동일하게 육안 확인

- [ ] 라이트 모드에서도 위 4개 항목 재확인
